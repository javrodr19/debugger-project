## Decomposition context

The V2 roadmap (lines 20–44 of the roadmap doc) bundles three independent subsystems under the V2 label:

- **A — Dynamic validation** (runtime-confirmed provenance tier, test-suite cross-check, debug-session cross-check, FP suppression memory, confidence pill UI). The trust-builder.
- **B — Python support** (full analyzer pipeline as a primary tier).
- **C — IDE-native integration** (Problems tool window, IntentionAction quick-fixes, inspection profile entries, streaming AI responses).

The user agreed during brainstorming to ship these as three separate sub-releases — **V2.0 = A**, **V2.1 = C**, **V2.2 = B** — each with its own spec → plan → implementation cycle. This spec covers V2.0 only. Sub-projects B and C will be specced separately once V2.0 ships.

Order rationale: A first because the roadmap explicitly identifies false-positive noise as the #1 reason users abandon analysis tools — trust must land before more fixers or languages. C second because the IDE-native pieces complement A (Problems-window entries benefit from the new confidence tier). B last because Python is the most insulated work and benefits from V2.0+V2.1 surface already being in place.

## Summary

V2.0 introduces **runtime confirmation** of static findings. Every finding produced by an analyzer gets a fourth provenance signal (`RUNTIME_CONFIRMED`) on top of the existing `STATIC` / `AI_LOCAL` / `AI_CLOUD` tags, surfaced as a visible confidence pill that drives a layered sort (severity primary, confidence secondary). Confirmation comes from two complementary sources: the IntelliJ test runner (failure stack traces + line-level coverage when available) and the IntelliJ debugger (variable values observed at pause). A separate suppression-memory layer auto-hides findings the user has dismissed repeatedly without runtime confirmation.

The change is **strictly additive**: zero V1.5 APIs change, the `Issue` data class is untouched, all existing collaborators continue to behave identically. New behavior lives in three new project-scoped services and two new `PersistentStateComponent`s, accessed only through the `GhostDebuggerService` facade per the CLAUDE.md ownership rules.

## Decisions made during brainstorming (with rationale)

| # | Decision | Rationale |
|---|---|---|
| 1 | V2.0 = all 5 roadmap bullets in one release | User explicitly accepted longer gap before release; preserves trust-story end-to-end on first user-visible V2.0 |
| 2 | Cover all 4 current-analyzer languages (TS, JS, Kotlin, Java) | Trust goal undermined if half the languages are second-class; JS/TS coverage support is a known investigation item but not a blocker |
| 3 | Trigger model: first-run nudge with persisted `Always / Ask each time / Never` choice | Respects "non-destructive" V1 principle; teaches users why coverage matters; default `Ask each time` avoids surprise |
| 4 | Persistence: workspace-scoped `PersistentStateComponent`, keyed by `Issue.fingerprint()` | Survives IDE restart (in-memory would feel like the feature broke); fingerprint-keyed lookup gives automatic invalidation on code change without explicit file watchers |
| 5 | Sort: layered within severity, confidence secondary | Preserves V1 muscle memory; existing users don't see their issue list reordered overnight |
| 6 | Architecture: separate `RuntimeEvidenceStore`, joined at display time | `Issue` model stays unchanged (V1.5 facade invariants); store follows "one writer, many readers" pattern; observers and UI decouple via reactive `evidenceChanged` events |

## Goals & success criteria

V2.0 ships when all seven hold:

1. **Functional** — A finding from any of the 4 analyzer-supported languages can be promoted to `CONFIRMED` via a test failure AND demoted via a debug observation. Verified by end-to-end smoke tests + manual acceptance on each language fixture.
2. **Non-regression** — Full V1.5 test suite continues to pass. No existing API behavior changes. Plugin loads on a project that has no `.idea/aegis-*.xml` files (clean install). Plugin loads on a project with V1.5-format settings (upgrade).
3. **PSC correctness** — Evidence persists across IDE restart, evidence GC happens on analysis re-run, schema mismatch dropped gracefully without user-visible error.
4. **UX integrity** — First-run nudge fires exactly once per project (or never, depending on user choice); confidence pills render in all 5 states; layered sort preserves V1 mental model.
5. **Privacy** — Zero new network calls. Zero new telemetry. Storage strictly workspace-local. Audit pass during PR review confirms no `.send`, `.post`, or network sink anywhere in new code.
6. **Performance** — Test suite runs in under 5 minutes (current ~232 tests + ~80 new tests). UI render latency on a 1000-finding list stays within V1.5's measured baseline.
7. **Test coverage** — ~80 new tests across the 5 layers described in the Testing strategy section. All passing on JBR-bound CI.

## Architecture overview

V1.5's facade (`GhostDebuggerService`) and four collaborators (`AnalysisOrchestrator`, `UIEventRouter`, `FileChangeWatcher`, `DebugSessionCoordinator`) are **untouched**. V2.0 adds a parallel layer of runtime-evidence collaborators alongside them. The two layers communicate at exactly one point: UI surfaces, where both analysis findings and runtime evidence are joined for display.

```
                       GhostDebuggerService (facade — V1.5)
                                │
            ┌───────────────────┼───────────────────┐
            ▼                   ▼                   ▼
    AnalysisOrchestrator   UIEventRouter   DebugSessionCoordinator
            │                   │                   │
            │  emits Issue[]    │  routes events    │  hooks XDebugger events
            ▼                   ▼                   ▼
    ┌─────────────────── existing V1.5 flow ─────────────────┐
    │           (issue list, detail panel, NeuroMap)         │
    └──────────────────────────┬─────────────────────────────┘
                               │
                               │ also read evidence from →
                               ▼
    ╔══════════════════════════════════════════════════════════╗
    ║                  NEW IN V2.0                             ║
    ║                                                          ║
    ║   ┌────────────────────────┐                             ║
    ║   │ RuntimeEvidenceStore   │  <── writes ── TestRunObserver
    ║   │ (PSC, by fingerprint)  │  <── writes ── DebugObserver  ║
    ║   └────────────────────────┘                             ║
    ║              ▲                                           ║
    ║              │ reads at render-time                      ║
    ║              │ + subscribes to evidenceChanged           ║
    ║   ┌────────────────────────┐                             ║
    ║   │ SuppressionMemoryService│  (separate PSC: dismiss counts)
    ║   └────────────────────────┘                             ║
    ╚══════════════════════════════════════════════════════════╝
```

Facade integration adds two accessors (mirroring V1.5's existing `jcefBridge()` pattern):
- `fun runtimeEvidenceStore(): RuntimeEvidenceStore`
- `fun suppressionMemory(): SuppressionMemoryService`

Direct service-locator access from elsewhere in the codebase is forbidden by the same CLAUDE.md rule that governs V1.5 collaborators — all access goes through the facade.

## Components

### `RuntimeEvidence` (data class, model layer)

```kotlin
data class RuntimeEvidence(
    val fingerprint: String,              // matches Issue.fingerprint()
    val source: EvidenceSource,
    val outcome: EvidenceOutcome,
    val timestamp: Long,                  // epoch millis, for staleness display only
    val context: String? = null           // e.g. "com.acme.UserTest.shouldRejectNull" or "MyFile.kt:42"
)

enum class EvidenceSource { TEST_FAILURE, TEST_COVERAGE, TEST_OUTCOME_PASS, DEBUG_OBSERVATION }
enum class EvidenceOutcome { CONFIRMED, LIKELY, DEMOTED, UNREACHED }
```

Immutable. Multiple `RuntimeEvidence` records per fingerprint allowed — e.g., one test confirmed it, one debug session also confirmed it. The store keeps the most recent N=5 per source per fingerprint and drops older ones on append.

### `RuntimeEvidenceStore` (project service + PSC)

```kotlin
@Service(Service.Level.PROJECT)
@State(name = "AegisRuntimeEvidence", storages = [Storage("aegis-runtime-evidence.xml")])
class RuntimeEvidenceStore(private val project: Project) :
    PersistentStateComponent<RuntimeEvidenceStore.State>, Disposable {

    data class State(
        var version: Int = 1,
        var entries: MutableMap<String, MutableList<RuntimeEvidence>> = mutableMapOf()
    )

    fun record(evidence: RuntimeEvidence)                       // append; cap list at N=5 per source; fire evidenceChanged (debounced)
    fun lookup(fingerprint: String): List<RuntimeEvidence>      // O(1) hashmap read
    fun lookupAll(): Map<String, List<RuntimeEvidence>>
    fun clearOrphans(activeFingerprints: Set<String>)           // called by facade after each analysis run
    fun addListener(listener: EvidenceChangedListener, parentDisposable: Disposable)

    fun interface EvidenceChangedListener {
        fun onEvidenceChanged(affected: Set<String>)
    }
}
```

Workspace storage (`Storage("aegis-runtime-evidence.xml")` defaults to workspace scope, lives in `.idea/`). Not committed to git. The orphan GC on every analysis run keeps the store from growing unbounded: stale evidence for findings that no longer exist gets dropped.

Concurrency: writes serialized via a single internal mutex. Reads are lock-free (read snapshot of state via `state`). Listeners fired off the write thread via `ApplicationManager.invokeLater` to keep observers off the EDT. 200ms debounce on `evidenceChanged` coalesces rapid-fire batch writes (e.g., debug-session multi-variable evaluation) into a single UI refresh.

### `TestRunObserver` (project service)

```kotlin
@Service(Service.Level.PROJECT)
class TestRunObserver(private val project: Project) : Disposable {
    init {
        project.messageBus.connect(this).subscribe(
            SMTRunnerEventsListener.TEST_STATUS,
            object : SMTRunnerEventsAdapter() {
                override fun onTestFailed(test: SMTestProxy) = recordFromFailure(test)
                override fun onTestFinished(test: SMTestProxy) = recordFromOutcome(test)
                override fun onTestingFinished(testsRoot: SMTestProxy.SMRootTestProxy) = harvestCoverage()
            }
        )
        CoverageDataManager.getInstance(project)
            .addSuiteListener(coverageListener, this)
    }

    private fun recordFromFailure(test: SMTestProxy)
    private fun recordFromOutcome(test: SMTestProxy)
    private fun harvestCoverage()
}
```

Two complementary write paths:
- **Failure-based** (works without coverage): a failing test produces a stack trace; we walk the trace, look up findings whose fingerprint matches `(file, line)` for each frame, write `TEST_FAILURE → CONFIRMED` evidence.
- **Coverage-based** (requires "Run with Coverage" — gated by the first-run nudge setting): after the suite finishes, walk all findings in the project, check coverage for `(file, line)`. If covered + test passed → `TEST_COVERAGE → LIKELY`. If never covered after this run → `TEST_COVERAGE → UNREACHED` **only when the run was a full suite run** (`bundle.isRootSuite`), to avoid false UNREACHED tags from single-test launches.

### `DebugObserver` (project service)

```kotlin
@Service(Service.Level.PROJECT)
class DebugObserver(private val project: Project) : Disposable {
    init {
        project.messageBus.connect(this).subscribe(
            XDebuggerManager.TOPIC,
            object : XDebuggerManagerListener {
                override fun processStarted(debugProcess: XDebugProcess) {
                    debugProcess.session.addSessionListener(SessionWatcher(), this@DebugObserver)
                }
            }
        )
    }

    private inner class SessionWatcher : XDebugSessionListener {
        override fun sessionPaused() = evaluateRelevantFindingsAtCurrentFrame()
    }

    private fun evaluateRelevantFindingsAtCurrentFrame() {
        // 1. Get current frame from XDebugSession.currentStackFrame
        // 2. Locate findings whose file matches the frame's source and line falls within the frame's function range
        // 3. For each finding type that supports debug confirmation: use XDebugSession.debugProcess.evaluator
        //    to evaluate the analyzer's tracked variable expression (from Analyzer.debugProbe(issue))
        // 4. Compare evaluated value to the analyzer's prediction
        //    - match (e.g., variable IS null on null-safety finding) → DEBUG_OBSERVATION → CONFIRMED
        //    - contradict (variable NON-null) → DEBUG_OBSERVATION → DEMOTED
        // 5. Write evidence to the store
    }
}
```

V2.0 implementation supports debug confirmation for two analyzer types: `NullSafetyAnalyzer` and a state-before-init check. Other analyzer types (complexity, circular deps, unused imports) cannot be debug-checked and the observer skips them via `Analyzer.debugProbe(issue)` returning `null`.

Async evaluation: `XDebugSession.evaluator.evaluate(expression, callback)` runs off the EDT. We must not block `sessionPaused`. If the user resumes before evaluation completes, the callback still fires and writes evidence (the variable's value at the paused moment was still valid). Per-finding try/catch (with PCE rethrow) means one failed evaluation doesn't abort the others.

### `SuppressionMemoryService` (project service + separate PSC)

```kotlin
@Service(Service.Level.PROJECT)
@State(name = "AegisSuppressionMemory", storages = [Storage("aegis-suppression-memory.xml")])
class SuppressionMemoryService(private val project: Project) :
    PersistentStateComponent<SuppressionMemoryService.State>, Disposable {

    data class State(
        var version: Int = 1,
        var dismissCounts: MutableMap<String, Int> = mutableMapOf()
    )

    fun recordDismissal(fingerprint: String)                      // increments count
    fun shouldAutoHide(fingerprint: String): Boolean              // count >= N AND no CONFIRMED in store AND no LIKELY in last 30 days
    fun reset(fingerprint: String)                                // user un-hides via "Show suppressed" toggle
    fun resetAll()                                                // settings-page "Reset all suppressions" link
    fun visibleCount(): Int                                       // for settings page display
}
```

Default `N = 3`. Settings page exposes it as configurable (1–10). Filter logic deliberately checks the runtime evidence store: a finding that was dismissed N times then later runtime-confirmed gets *resurfaced*, because runtime evidence overrides historical dismissals. The "no LIKELY in last 30 days" rule is a soft-recency guard: if a finding has been recently covered (even passing), assume it's still a real candidate worth showing rather than hiding it.

### `ConfidenceCalculator` (pure helper)

```kotlin
object ConfidenceCalculator {
    fun calculate(evidence: List<RuntimeEvidence>): Confidence = when {
        evidence.isEmpty() -> Confidence.UNCONFIRMED
        evidence.any { it.outcome == EvidenceOutcome.CONFIRMED } -> Confidence.CONFIRMED
        evidence.any { it.outcome == EvidenceOutcome.DEMOTED } &&
            evidence.none { it.outcome == EvidenceOutcome.CONFIRMED } -> Confidence.DEMOTED
        evidence.any { it.outcome == EvidenceOutcome.LIKELY } -> Confidence.LIKELY
        evidence.all { it.outcome == EvidenceOutcome.UNREACHED } -> Confidence.UNREACHED
        else -> Confidence.UNCONFIRMED
    }
}

enum class Confidence { CONFIRMED, LIKELY, UNCONFIRMED, UNREACHED, DEMOTED }
```

Precedence: any `CONFIRMED` wins. `DEMOTED` only sticks if there's no `CONFIRMED` to override it. `LIKELY` beats `UNCONFIRMED`. `UNREACHED` only applies when ALL evidence agrees nothing's executed.

### `EvidenceSubscriptionAdapter` (UI-layer helper)

```kotlin
object EvidenceSubscriptionAdapter {
    /**
     * Subscribes a UI surface to evidenceChanged events with uniform EDT marshaling and
     * per-listener exception isolation. Auto-disposed via the parent Disposable.
     */
    fun subscribe(parent: Disposable, onAffected: (Set<String>) -> Unit)
}
```

A small object that wraps `RuntimeEvidenceStore.addListener` with three concerns the three UI surfaces (issue list, detail panel, NeuroMap) would otherwise duplicate:
- EDT marshaling — listener callback always runs on the EDT regardless of store thread.
- Per-listener exception isolation — if one subscriber throws, others still fire (PCE rethrown first per the convention).
- `Disposer` registration — subscription dies when the parent UI surface is disposed.

Each UI surface becomes a one-liner: `EvidenceSubscriptionAdapter.subscribe(this) { affected -> refreshRows(affected) }`. No subscriber implements the boilerplate themselves.

### `Analyzer` interface change

```kotlin
interface Analyzer {
    // ... existing methods unchanged ...

    /**
     * Returns the expression string to evaluate in the current debug frame, or null if this
     * analyzer's findings cannot be debug-confirmed. Default implementation returns null.
     * Backwards-compatible: all existing analyzers compile without modification.
     */
    fun debugProbe(issue: Issue): String? = null
}
```

Only `NullSafetyAnalyzer` and the state-before-init check override the default in V2.0. The interface change is the only Analyzer-level API addition in this release.

## Data flow

### Flow A — Analysis run (existing path + new evidence join)

```
User edits file / triggers analysis
  └─→ AnalysisOrchestrator runs analyzers (BGT)                              [V1.5 unchanged]
        └─→ produces Issue[] with stable fingerprints                         [V1.5 unchanged]
              └─→ facade.updateIssues(...)                                    [V1.5 unchanged]
                    ├─→ UIEventRouter dispatches to UI surfaces (EDT)         [V1.5 unchanged]
                    │     └─→ each surface, when rendering an Issue:
                    │           ├─→ evidence = store.lookup(issue.fingerprint())     [NEW]
                    │           ├─→ confidence = ConfidenceCalculator.calculate(...) [NEW]
                    │           └─→ pill rendered, sort applied                      [NEW]
                    └─→ store.clearOrphans(activeFingerprints)               [NEW] GC
```

No new code in `AnalysisOrchestrator`. The orphan GC is invoked from the facade's `updateIssues(...)` after dispatch, since the facade already knows the full set of active fingerprints.

### Flow B — Test run *without* coverage (failure-only path)

```
User clicks "Run" on a test config (no coverage)
  └─→ IntelliJ launches test process
        └─→ SMTRunnerEventsAdapter.onTestFailed(test)   [BGT, message bus]
              └─→ TestRunObserver.recordFromFailure(test):
                    ├─→ parse test.stacktrace into List<StackFrame>
                    ├─→ for each frame, query facade.currentIssues for findings
                    │   at (frame.file, frame.line)
                    ├─→ for each matching finding:
                    │     store.record(RuntimeEvidence(
                    │         fingerprint = finding.fingerprint(),
                    │         source      = TEST_FAILURE,
                    │         outcome     = CONFIRMED,
                    │         timestamp   = now,
                    │         context     = "${test.fullyQualifiedName}"
                    │     ))
                    └─→ store fires evidenceChanged(affectedFingerprints) → UI refresh
```

Stack-trace parsing is per-language. JVM frames look like `at com.acme.Foo.bar(Foo.kt:42)`. JS/TS frames look like `at bar (webpack:///./src/Foo.ts:42:7)`. The V1 NeuroMap path-resolver already handles JVM frames; JS/TS frame handling needs verification during planning (open investigation item).

### Flow C — Test run *with* coverage (full path)

```
User clicks "Run with Coverage" (or always-coverage via nudge setting)
  └─→ IntelliJ launches test process with coverage instrumentation
        └─→ during run: SMTRunnerEventsAdapter.onTestFailed → same as Flow B
        └─→ run finishes:
              ├─→ SMTRunnerEventsAdapter.onTestingFinished fires
              ├─→ CoverageDataManager.coverageGathered fires (after instrumented data is loaded)
              └─→ TestRunObserver.harvestCoverage():
                    ├─→ get CoverageSuitesBundle from CoverageDataManager
                    ├─→ for each finding in facade.currentIssues:
                    │     ├─→ classData = bundle.getClassData(finding.qualifiedClass)
                    │     ├─→ if classData == null && bundle.isRootSuite:
                    │     │     store.record(... outcome = UNREACHED ...)
                    │     ├─→ else if line was executed:
                    │     │     store.record(... outcome = LIKELY, source = TEST_COVERAGE ...)
                    │     └─→ (CONFIRMED still wins from any prior TEST_FAILURE in this run)
                    └─→ evidenceChanged fires once for the whole batch
```

`bundle.isRootSuite` is the gate that prevents single-test launches from falsely tagging unrelated classes as UNREACHED.

### Flow D — Debug session pause

```
User hits a breakpoint, or steps onto a paused line
  └─→ XDebugSessionListener.sessionPaused()                  [EDT, must not block]
        └─→ DebugObserver.evaluateRelevantFindingsAtCurrentFrame():
              ├─→ frame = session.currentStackFrame
              ├─→ find Issues whose file == frame.source AND
              │   line ∈ frame.function.range
              ├─→ for each such Issue, ask its analyzer for debugProbe(issue):
              │     ├─→ if null → skip (analyzer doesn't support debug confirmation)
              │     └─→ if non-null → expression string (e.g., "userInput")
              ├─→ for each (issue, expression):
              │     └─→ session.debugProcess.evaluator.evaluate(expression, callback)  [BGT]
              │           └─→ callback receives XValue:
              │                 ├─→ match analyzer's prediction → CONFIRMED
              │                 ├─→ contradicts                → DEMOTED
              │                 └─→ inconclusive (XErrorValue) → skip
              ├─→ as each callback returns, store.record(...) is called
              └─→ store fires evidenceChanged once after a 200ms debounce window
                  to batch the multiple async callbacks into a single UI refresh
```

### Flow E — Suppression filter at display time

```
UI surface about to render the issue list
  └─→ for each Issue in facade.currentIssues:
        ├─→ if facade.suppressionMemory().shouldAutoHide(issue.fingerprint()):
        │     ├─→ if "Show suppressed" toggle is OFF → skip (don't render)
        │     └─→ else → render with reduced opacity + "SUPPRESSED" chip
        └─→ otherwise → render normally, with confidence pill from Flow A logic
```

`shouldAutoHide` reads both the suppression PSC AND the runtime evidence store. A previously-dismissed finding that has since been runtime-confirmed gets resurfaced. User dismissals via the existing "Dismiss" button additionally call `suppressionMemory.recordDismissal(fingerprint)` — dismiss behavior from the user's perspective is unchanged.

### Mid-session evidence-changed propagation

The store fires `evidenceChanged(affected: Set<String>)`. Subscribers (issue list panel, detail panel, NeuroMap) go through `EvidenceSubscriptionAdapter` — a small helper that handles EDT marshaling, debouncing of rapid-fire events, and `Disposer` registration. Each subscriber does `EvidenceSubscriptionAdapter.subscribe(this, ::onAffected)` — uniform one-liner setup.

`UIEventRouter` does NOT subscribe. The store talks directly to UI surfaces. Rationale: `UIEventRouter` routes analysis state changes; runtime evidence is a separate dimension and routing it through the router would couple two unrelated state surfaces.

Suppression filter happens at *display time* in the UI surfaces, not in `AnalysisOrchestrator`'s merge step. That means `facade.currentIssues` always contains the full list — auto-hiding is purely a render-layer concern.

## Settings & UX

### New settings panel: "Dynamic Validation"

Lives under the existing Aegis settings root (`settings/AegisConfigurable.kt`).

| Control | Type | Default | Stored as |
|---|---|---|---|
| Use coverage for test runs | Radio: `Always` / `Ask each time` / `Never` | `Ask each time` | `AegisSettingsState.coverageMode` |
| Suppression threshold | Integer 1–10 | `3` | `AegisSettingsState.suppressionThreshold` |
| Show unreached findings | Checkbox | `false` | `AegisSettingsState.showUnreached` |
| Show suppressed findings | Checkbox | `false` | `AegisSettingsState.showSuppressed` |

Below the controls, a read-only info line: *"N findings are currently auto-hidden. [Reset all suppressions]"* where N is `suppressionMemory.visibleCount()` and the link calls `suppressionMemory.resetAll()`. Changing any setting fires `evidenceChanged(allFingerprints)` so the UI reflects the change immediately without IDE restart.

### First-run nudge

Trigger: when `TestRunObserver.onTestingFinished` fires AND `settings.coverageMode == "Ask each time"` AND `CoverageDataManager.getCurrentSuitesBundle(project)` is null AND the nudge hasn't been shown this IDE session for this project.

Notification via the existing IntelliJ notification framework, new sub-group `Aegis Suggestions` registered in `plugin.xml` (type INFORMATION):

```
[Aegis Debug] Aegis confirms more findings when tests run with coverage.
Switch to Run with Coverage for this project?

  [ Always use coverage ]   [ Not this time ]   [ Never ask again ]
```

- "Always use coverage" → sets `coverageMode = Always`. On next test launch, a small `ExecutionListener` (subscribed to `ExecutionManager.EXECUTION_TOPIC`) intercepts test launches and substitutes `CoverageExecutor` for `DefaultRunExecutor`. The user's manual toolbar invocation of "Run" is not intercepted — only the implicit click on test configs.
- "Not this time" → no settings change; nudge appears again on next non-coverage test run, with a one-hour cooldown.
- "Never ask again" → sets `coverageMode = Never`; nudge suppressed for this project.

Open investigation item: confirm `ExecutionListener.processStartScheduled` is the correct hook for executor substitution (vs `processStarting` which may be too late).

### Confidence pill rendering

New Swing component `ConfidencePill` (JLabel subclass under `toolwindow/`). Small rounded chip, ~14px tall, 4px horizontal padding, color-coded via `JBColor` (Darcula-adaptive):

| State | Background | Foreground | Label |
|---|---|---|---|
| `CONFIRMED` | `#1F8B4C` (green) | white | `CONFIRMED` |
| `LIKELY` | `#2E5BBA` (blue) | white | `LIKELY` |
| `UNCONFIRMED` | `#6B7280` (gray) | white | `UNCONFIRMED` |
| `UNREACHED` | `#B45309` (amber) | white | `NEEDS COVERAGE` |
| `DEMOTED` | `#B91C1C` (faded red, alpha 60%) | white, italic | `DEMOTED` |

Same component renders in three places:
1. **Issue list row** — between the severity icon and the issue title, ~85px width.
2. **Detail panel header** — same component, larger font, next to the finding's severity badge.
3. **NeuroMap node tooltip** — as colored dots per confidence tier with counts, e.g., `● 3 CONFIRMED · ● 2 UNCONFIRMED`.

The NeuroMap node itself doesn't change color based on confidence — severity stays the visual primary for the map to preserve V1 muscle memory.

### Issue list sort (layered)

Sort comparator becomes:

```kotlin
compareBy<Issue>(
    { it.severity.ordinal },                       // ERROR=0 first (existing)
    { ConfidenceCalculator.calculate(store.lookup(it.fingerprint())).rank() },
                                                   // CONFIRMED=0 first within severity (NEW)
    { it.filePath },                               // existing tiebreaker
    { it.line }                                    // existing tiebreaker
)

// Confidence.rank(): CONFIRMED=0, LIKELY=1, UNCONFIRMED=2, DEMOTED=3, UNREACHED=4
```

Per-render `store.lookup(...)` calls are O(1) hashmap reads; even on a 1000-finding list well under a millisecond.

### Suppression management UX

In the issue list, a chevron strip at the top when `visibleCount() > 0` and `showSuppressed = false`:

> *"3 findings auto-hidden — [Show]"*

Clicking [Show] flips the setting and re-renders. Each auto-hidden finding, when shown, appears at the bottom of its severity group with:
- 50% opacity on the whole row
- An extra `SUPPRESSED` chip (dark gray) next to the confidence pill
- Right-click context menu adds "Un-suppress this finding" → `suppressionMemory.reset(fingerprint)`

When a user dismisses a finding (existing V1 "Dismiss" button), the action additionally calls `suppressionMemory.recordDismissal(fingerprint)`. Existing dismiss UX is unchanged from the user's perspective.

## Error handling

The CLAUDE.md conventions here are non-negotiable: PCE always rethrows, analyzer bias preserved (no false positives), and silent failure is forbidden (V1.4.1 fixed exactly this class of bug).

### PCE discipline (universal)

Every `catch (e: Exception)` block in all new code (`RuntimeEvidenceStore`, `TestRunObserver`, `DebugObserver`, `SuppressionMemoryService`, `ConfidenceCalculator`, `EvidenceSubscriptionAdapter`, settings/UI integration code) begins with:

```kotlin
if (e is ProcessCanceledException) throw e
```

Enforced by code review. No new catch-all wrapper — putting one in would obscure exactly the kind of platform-state exception V1.4.1's audit fixed.

### Test observation failure modes

| Failure | Behavior |
|---|---|
| `CoverageDataManager` returns null suite bundle (user did plain "Run") | `harvestCoverage()` is a no-op. `recordFromFailure()` still runs from stack traces. Logged at INFO. |
| Stack trace fails to parse (obfuscated JS, unknown format) | Per-frame parse wrapped in try/catch; failed frame skipped, remaining frames continue. Logged at DEBUG. Never aborts the whole observation. |
| Stack frame doesn't match any finding (test fails in third-party code) | Lookup returns empty list; nothing recorded. No error. |
| `SMTestProxy.fullyQualifiedName` null (non-standard runner) | Evidence still recorded; `context = "<unnamed test>"`. |
| Project disposed mid-run | Observer's message-bus subscription auto-disposed via `Disposer` chain. In-flight writes swallowed (project gone, nothing to write to). |

### Debug observation failure modes

| Failure | Behavior |
|---|---|
| `XDebugSession.evaluator` returns null (Python pre-debugpy, some KMP targets) | `evaluateRelevantFindingsAtCurrentFrame()` returns early. Logged INFO once per session (not per pause). |
| Evaluator callback returns `XErrorValue` (variable out of scope) | Treated as inconclusive. No CONFIRMED, no DEMOTED — skip. |
| User resumes session before async callback returns | Callback still fires; if session/project not disposed, evidence recorded (variable's value at paused moment still valid). |
| Evaluator throws `EvaluationException` | Per-finding try/catch (with PCE rethrow), skip that finding, continue. |
| `XDebugSession.currentStackFrame` null (race window) | Return early; observer fires again on `stackFrameChanged`. |
| Multiple debug sessions simultaneously | Each session has its own `SessionWatcher` (per-process). Store mutex serializes concurrent writes. |

### Storage failure modes

| Failure | Behavior |
|---|---|
| XML corruption (half-written file from crash) | `XmlSerializationException` caught in `loadState`, logged WARN, initialize empty state. Evidence rebuilt on next test/debug run. |
| State map unbounded growth | `clearOrphans()` on every analysis run bounds it. Belt-and-suspenders: `loadState` drops entries older than 30 days when count > 50,000. |
| Schema version mismatch (`state.version != 1`) | Drop entries silently, start fresh. Data is not user-precious. |
| Concurrent writes | Internal mutex in `RuntimeEvidenceStore.record()` serializes. PSC's `getState()` hands the platform a copy of state — no contention with writes. |

### Subscription/listener failure modes

| Failure | Behavior |
|---|---|
| Subscriber throws during `onEvidenceChanged` | `EvidenceSubscriptionAdapter` catches per-listener (with PCE rethrow), logs WARN with listener class name, continues notifying remaining listeners. |
| IDE removes/renames an SPI in a future release | `./gradlew verifyPlugin` catches at build time. Platform floor pinned in `build.gradle.kts`. |
| User uninstalls test framework plugins | Observers fail silently to register (nothing publishes to the listened topic). Logged once at INFO on plugin startup. |

### Concurrency edge cases

| Scenario | Behavior |
|---|---|
| Two test suites in parallel (Gradle parallel execution) | Each suite's SMTRunnerEvents handled in isolation; coverage bundles processed sequentially via mutex. |
| Test run finishes while debug session paused | Both observers write to the same store; mutex serializes; UI sees one batched `evidenceChanged` after the 200ms debounce. |
| Analysis re-runs while test run in progress | `clearOrphans()` runs on analysis completion. If finding fingerprint changed mid-test, old evidence GC'd; next test run re-confirms. Race window seconds; cost: one extra test run. |
| Project closed during evidence write | Write paths check `project.isDisposed` before touching state; `Disposer` chain disposes the store gracefully. |

### Analyzer-bias preservation

The runtime-evidence layer respects the V1 trust contract from CLAUDE.md: "When the Analysis API can't decide, analyzers DO NOT flag. False positives erode trust faster than false negatives."

Applied to V2.0:
- **Never CREATE a finding from runtime evidence.** Evidence only enriches existing static findings. If a debug session shows a variable was null somewhere with no static finding, we do nothing.
- **Demotion never hides a finding entirely.** A DEMOTED finding is still visible (with its badge); the user decides whether to dismiss. This protects against the case where a debug-observation demote is itself wrong (user paused on a path where the variable was non-null, but other paths exist where it could be null).
- **Confirmation never elevates severity.** A CONFIRMED `INFO` stays an `INFO`. The analyzer's severity judgment is independent of runtime confirmation.
- **UNREACHED only applies on whole-suite runs**, never single-test runs.

### Logging discipline

All new code uses `Logger.getInstance(<class>)` (V1 convention). Log levels:
- ERROR: never used by V2 code — runtime evidence failures are recoverable, not errors.
- WARN: storage corruption, subscriber exceptions, persistent SPI unavailability.
- INFO: first-time observations of expected-degraded modes (no coverage, no evaluator).
- DEBUG: per-event detail (frame skipped, individual variable evaluations).

No `println`, no `e.printStackTrace()`, no swallowed exceptions without a log line.

### Test infrastructure additions

New base class **`AegisRuntimeEvidenceTestCase`** (extends `BasePlatformTestCase`) provides:
- Fresh `RuntimeEvidenceStore` per test (registered as project service for the fixture).

- **Real debug-session integration** — same reason; mock `XDebugSession` is the closest we get.
- **Plugin verifier output** — build-time concern, not a unit test.

## Migration & compatibility

### From V1.5 → V2.0

**Strictly additive.** Zero V1.5 APIs change. Zero V1.5 settings keys change.

| Migration item | Behavior |
|---|---|
| Existing `AegisSettingsState` | Unchanged. New keys (`coverageMode`, `suppressionThreshold`, `showUnreached`, `showSuppressed`, `nudgeShownOnce`) added with defaults; PSC framework handles absent keys by returning defaults. |

| `Analyzer` interface | Adds `fun debugProbe(issue: Issue): String? = null` — default returns null, backwards-compatible. Only `NullSafetyAnalyzer` and state-before-init analyzer override in V2.0. |

## Open investigation items for planning phase

These are known unknowns the implementation plan must resolve. Each is a small spike, not a blocker:

| Item | What to verify |
|---|---|
| **JS/TS coverage in Community edition** | Does `CoverageDataManager` produce usable bundles for Jest/Vitest/Mocha in Community? If yes → ship all 4 languages quietly. If no → ship with explicit "best in Ultimate" copy. |
| **`SMTRunnerEventsListener` for JS** | Does the JS test runner publish to the same `TEST_STATUS` topic via SM protocol? If yes → one observer handles all four languages. If no → may need JS-specific listener. |
| **`ExecutionListener` hook for coverage-rewrite** | Is `processStartScheduled` the right hook for substituting `CoverageExecutor`? If not, where? |
| **JS/TS stack-trace formats** | Verify V1's existing stack-frame parser (NeuroMap path resolution) handles webpack-source-mapped frames. If not, port/extend for V2.0. |
| **`Issue.fingerprint()` memoization** | V1.5 deferred memoization. V2.0's per-render lookup calls `fingerprint()` many times. Profile first; only memoize if it shows up in trace. |

## Risks

| Risk | Probability | Mitigation |
|---|---|---|
| `CoverageDataManager` SPI varies subtly between IDE editions/versions | Medium | Investigation item above + plugin verifier on multiple builds. If late blocker, downgrade JS/TS to failure-only confirmation and ship. |
| `XDebugSession.evaluator` null for Kotlin coroutines/suspend frames | Medium | Documented degradation. Falls back to UNCONFIRMED for suspend frames. No user-facing error. |
| Persisted evidence diverges from current code state | Low | Fingerprint changes on most code edits → orphan GC drops stale evidence on next analysis. |
| First-run nudge feels intrusive | Low | Nudge fires after a test run (not on plugin install). "Never ask again" is one of three top-level buttons. |
| Confidence pill clutter on issue list | Low | Pill ~85px; existing rows can absorb it. Manual UX validation against V1.5 baseline during implementation. |
| Performance regression from per-render `store.lookup` | Very low | O(1) hashmap reads. Profile during implementation; abort to caching strategy only if it shows up. |
| V2.2 (Python) finds the V2.0 architecture doesn't generalize | Low-medium | Store, observers, calculator all language-agnostic. Python adds analyzers + test-runner mapping; runtime-evidence layer absorbs Python without rework. |

## What this design intentionally over-builds

- **Unbounded-growth guard** in `RuntimeEvidenceStore.loadState` (drop entries >30 days old when count exceeds 50k). Belt to the orphan-GC suspenders.
- **Schema versioning** on PSC state (`version: Int = 1`) even though V2.0 ships v1. Cheap to add now, painful to retrofit later.

## What this design intentionally under-builds

- **No branch-aware evidence storage.** Fingerprint mismatch is the cheap proxy. Add in V2.0.1 if branch-hopping confusion becomes a real complaint.
- **No "Sort by: Confidence" toggle in the toolwindow header.** Default is layered. Add toggle in V2.0.1 if requested.
- **No real-debug end-to-end test.** Layered-mock coverage is sufficient.
- **No `Issue.fingerprint()` memoization** unless profiling shows a need.
