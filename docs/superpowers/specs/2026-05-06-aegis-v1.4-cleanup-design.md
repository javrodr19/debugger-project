**Date:** 2026-05-06

## 0. Summary

V1.4 closes the audit-surfaced gaps from V1.3 plus one user-reported bug. Six dependency-ordered commits on a single `v1.4-cleanup` branch:

1. **Marketplace copy + 1.2.0 change-notes + CLAUDE.md.** Refresh stale analyzer/fixer counts in `plugin.xml`, `build.gradle.kts`, `README.md`. Backfill the missing 1.2.0 entry in plugin.xml `<change-notes>`. Add a project-root `CLAUDE.md` documenting build prerequisites and conventions.
2. **Report-export rewrite.** Replace `ReportGenerator`'s raw-string + `trimIndent()` rendering (which leaks 12 spaces of leading whitespace per line into the output) with a `StringBuilder`-based renderer. Replace the `tmpdir + Desktop.browse()` flow with a `FileSaverDialog` + IDE notification offering "Open in browser" / "Show in Files" actions. Fix the `replace("/", "/")` no-op typo.
3. **Deprecated API replacement + Java regex fallback enrichment.** Swap the V1.3-flagged `KaExpressionTypeProvider.getReturnType(KtDeclaration)` deprecation for the symbol-based path. Extend the Java regex fallback to populate `returnType` and `paramTypes` on a best-effort basis.
4. **Smart-cast walker.** Add an `effectiveTypeWithStructuralSmartCast` helper in `KotlinAnalysisHelpers` that detects `is`-checks, `if (x != null)` blocks, and Elvis-return guards via parent-chain walking. The three V1.3-documented smart-cast known limitations flip from documented to fixed.
5. **AI prompt builder consumer for `returnType` / `paramTypes`.** Splice rendered signatures into `detectIssues` and `jointFix` prompt entries for JVM-language functions. TS/JS path unchanged (empty fields → no signature in output).
6. **Test backfill + performance smoke.** Add the V1.3-deferred fixer tests (`KotlinUnsafeCastFixerTest`, `KotlinRedundantLetFixerTest`), extractor enrichment canaries, smart-cast walker direct tests, and the V1.3 acceptance-criterion-#5 performance smoke entry.

V1.3 shipped at 192 green tests with `verifyPlugin` Compatible across IU 2024.3.2.2 / 2025.1 / 2026.1. V1.4 must preserve a green bar (target ~232) and a Compatible verdict against the same matrix.

## 3. Architecture

### 3.1 Branch + version

### 3.2 Report HTML rendering: StringBuilder

`ReportGenerator.generateHTMLReport` switches from interpolated raw strings + `trimIndent()` to a `StringBuilder` that emits HTML in line order. Pattern:

```kotlin
fun generateHTMLReport(graph: ProjectGraph): String = buildString {
    appendLine("<!DOCTYPE html>")
    appendLine("<html lang=\"en\">")
    appendLine("<head>")
    // ...
    appendLine("<title>Aegis Debug Report - ${htmlEscape(graph.metadata.projectName)}</title>")
    // ...
    append(buildIssuesList(graph))
    // ...
}
```

`buildIssuesList` and `buildNodesOverview` similarly use `StringBuilder`. No nested `trimIndent()`. Output starts at column 0, contains real newlines, and is byte-for-byte deterministic given the same `ProjectGraph` (modulo `LocalDateTime.now()`, which the test path will inject as a fixed value via constructor parameter or test seam).

### 3.3 Report export UX: `FileSaverDialog` + IDE notification

`handleExportReportRequested` rewrites:

```kotlin
private fun handleExportReportRequested() {
    val graph = currentGraph ?: run {
        notifyError("No analysis data available. Run 'Analyze Project' first.")
        return
    }

    scope.launch(Dispatchers.Swing) {
        val descriptor = FileSaverDescriptor(
            "Export Aegis Debug Report",
            "Choose where to save the analysis report",
            "html"
        )
        val dialog = FileChooserFactory.getInstance().createSaveFileDialog(descriptor, project)
        val defaultName = "aegis-debug-${sanitizeFilename(project.name)}-${System.currentTimeMillis()}.html"
        val saved = dialog.save(null as VirtualFile?, defaultName) ?: return@launch  // user cancelled

        scope.launch {
            try {
                val html = ReportGenerator().generateHTMLReport(graph)
                val outFile = saved.file
                outFile.writeText(html)
                withContext(Dispatchers.Swing) {
                    notifySuccessWithActions(outFile)
                }
            } catch (e: Exception) {
                log.error("Failed to write report", e)
                withContext(Dispatchers.Swing) {
                    notifyError("Export failed: ${e.message}")
                }
            }
        }
    }
}

private fun notifySuccessWithActions(file: File) {
    NotificationGroupManager.getInstance()
        .getNotificationGroup("GhostDebugger")
        .createNotification("Aegis Debug report exported", file.name, NotificationType.INFORMATION)
        .addAction(NotificationAction.create("Open in browser") { _, _ -> BrowserUtil.browse(file) })
        .addAction(NotificationAction.create("Show in Files") { _, _ -> RevealFileAction.openFile(file) })
        .notify(project)
}
```

`notifyError` is a thin wrapper around the existing `bridge?.sendError` call to preserve the error-toast surface for genuine failures.

### 3.4 Smart-cast walker

New helper in `parser/KotlinAnalysisHelpers.kt`:

```kotlin
internal fun KaSession.effectiveTypeWithStructuralSmartCast(expr: KtExpression): KaType?
```

Algorithm:

1. Try `effectiveType(expr)` (existing helper, consults `smartCastInfo` + `expressionType`). If non-null and non-`KaErrorType`, return it as candidate.
2. If candidate is nullable and `expr` is a `KtNameReferenceExpression`, walk the parent chain looking for narrowing constructs:
   - Surrounding `KtIfExpression` whose condition is `<name> is <T>` or `<name> != null` — then `expr` is in the then-branch (not else).
   - Preceding sibling `KtBinaryExpression` with operator `?:` (Elvis) and right side `KtReturnExpression` / `KtThrowExpression` on the same name.
   - Surrounding `KtWhenEntry` whose condition is `is <T>`.
3. If a narrowing context is found and the variable hasn't been reassigned between guard and use, return the narrowed type (non-null base type for `is`/`!= null`; specific `T` for `is T`).
4. Otherwise return the candidate type unchanged.

Walker stops at function-boundary nodes (`KtNamedFunction`, `KtLambdaExpression`, `KtClassInitializer`) — narrowing doesn't cross them.

The existing `effectiveType` is still used directly by analyzers that don't need structural narrowing (e.g., `KotlinTypeMismatchAnalyzer`, which operates on declarations). The three Kotlin analyzers affected by V1.3's known limitations (`KotlinNullSafetyAnalyzer`, `KotlinUnsafeCastAnalyzer`, `KotlinRedundantLetAnalyzer`) swap to the new walker.

### 3.5 AI prompt consumer

`PromptTemplates.kt` already iterates `parsedFile.functions` to build per-function lines. The current shape is something like:

```
- greet (line 3)
- add (line 7)
```

The new shape conditionally adds signature info:

```kotlin
val sig = buildString {
    append(fn.name)
    append('(')
    append(fn.paramTypes.joinToString(", "))
    append(')')
    fn.returnType?.let { append(": ").append(it) }
}
appendLine("- $sig  (line ${fn.line})")
```

For TS/JS files where `paramTypes` is empty and `returnType` is null, output is `- greet()  (line 3)` — slight format change but no FQN leakage. For JVM files: `- greet(String): String?  (line 3)`.

### 3.6 Deprecated API replacement

In `KotlinPsiSymbolExtractor.fromPsi` enrichment block:

```kotlin
// Before (V1.3, deprecated):
val ret = named.returnType.takeIf { !it.isUnitType }?.let { renderShort(it) }
val params = named.valueParameters.map { p -> renderShort(p.returnType) }

// After (V1.4, symbol-based):
val symbol = named.symbol as? KaFunctionSymbol ?: return@map fs
val ret = symbol.returnType.takeIf { !it.isUnitType }?.let { renderShort(it) }
val params = symbol.valueParameters.map { p -> renderShort(p.returnType) }
```

Same data, non-deprecated entry point. The `symbol` extension on `KtNamedFunction` inside `KaSession` is the canonical 2024.3+ access path.

### 3.7 Java regex fallback enrichment

Current regex captures only the method name:

```kotlin
private val JAVA_METHOD_REGEX = Regex(
    "(?:public|private|protected|static|\\s)+[\\w<>\\[\\]]+\\s+(\\w+)\\s*\\([^)]*\\)"
)
```

Extended to capture return type and parameter list:

```kotlin
private val JAVA_METHOD_REGEX = Regex(
    "(?:public|private|protected|static|\\s)+([\\w<>\\[\\]]+)\\s+(\\w+)\\s*\\(([^)]*)\\)"
)
```

Match block populates `returnType` and `paramTypes` from the captures:

```kotlin
JAVA_METHOD_REGEX.find(trimmed)?.let { match ->
    val returnTypeText = match.groupValues[1]
    val name = match.groupValues[2]
    val paramList = match.groupValues[3]
    if (name !in JAVA_RESERVED) {
        val paramTypes = if (paramList.isBlank()) emptyList()
                         else paramList.split(",").map { it.trim().substringBefore(" ").trim() }
                                                    .filter { it.isNotBlank() }
        functions.add(FunctionSymbol(
            name = name, line = index + 1, body = trimmed.take(120),
            returnType = returnTypeText, paramTypes = paramTypes
        ))
    }
}
```

Best-effort: complex generics / annotations may produce odd captures, but the fallback path is rarely exercised in practice (PSI is the primary path for Java).

## 9. Explicit non-goals for V1.4

V1.4 is **not**:

- Report format alternatives (CSV, JSON, Markdown) — HTML only
- Settings UI for default report directory — relies on FileSaverDialog's last-used-path memory
- Marketplace listing graphics, screenshots, pricing — text refresh only
- Cleanup of pre-existing 2026.1 deprecation warnings beyond `getReturnType`
- Smart-cast inside `&&` / `||` boolean conditions (OQ4: opportunistic if cheap, otherwise stays known-limitation)
- `KaErrorType` wrapping fix for unresolved-call type-mismatch (V1.1 broken-file gate handles in production)
- Backporting any V1.4 fix as a 1.3.1 patch
- New analyzers, new fixers, new languages — V2 territory
