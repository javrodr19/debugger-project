# Aegis Debug V1.4.1 — Audit-driven correctness, safety, and observability fixes

**Date:** 2026-05-10
**Status:** Draft — pending review
**Version target:** `1.4.1` (patch release; bundled commits, V1.4 pattern)
**Base branch:** `main` (at `658ea50`)
**Target working branch:** `v1.4.1-audit-fixes`

---

## 0. Summary

V1.4.1 closes the gaps surfaced by the post-V1.4 codebase audit (2026-05-10). Eight dependency-ordered commits on a single `v1.4.1-audit-fixes` branch:

1. **Marketplace copy + version bump + CHANGELOG stub.** `1.4.0` → `1.4.1` in `build.gradle.kts`, plugin.xml `<change-notes>`, README. CHANGELOG 1.4.1 section. No analyzer/fixer count change.
2. **PCE rethrow hardening.** Fix the two catch blocks that swallow `ProcessCanceledException` (`AnalysisEngine.runOne`, `CompilationErrorAnalyzer.harvestFile`). The first is the most consequential bug in the audit: a Cancel click during analysis is silently ignored and the next analyzer keeps running.
3. **`JcefBridge` JSON-encoding hardening.** Replace the eight hand-built JSON payloads (which escape only `"` and break on `\`, newlines, and control chars) with `kotlinx.serialization` `encodeToString` calls. Eliminates a JCEF JS-injection / payload-corruption class.
4. **`InMemoryGraph` concurrency + iterative cycle detection.** Adjacency-list inner sets become concurrent (`ConcurrentHashMap.newKeySet`); `findCycles` rewritten as iterative DFS over an explicit stack to remove the recursion-depth ceiling on monorepo-scale graphs.
5. **HTTP and cache hardening + observability.** Wrap OkHttp `Response` in `use { }` blocks (`OllamaService`, `OpenAIService`). Replace `AICache.get` get-then-remove TOCTOU pattern with `compute`. Add `log.warn` to `ApiKeyManager` env-var fallback and `log.info` to `AIAnalyzer` large-file skip.
6. **Fixer / analyzer correctness.** `NullSafetyFixer` switches from line-text regex replace to PSI-based `KtDotQualifiedExpression` rewrite (current implementation rewrites in strings/comments). `NullSafetyAnalyzer` comment skip extended to mid-line `//`. `NullSafetyAnalyzer` per-file scan switches to a single combined regex (O(N) instead of O(N × M)).
7. **Model cleanup.** Replace `ParsedFile.content = ""` mutation hack with an explicit `ParsedFile.dropContent()` method (or rename to a clearer pattern that doesn't reach into a `var`); `KotlinPsiSymbolExtractor.body = el.text.take(120)` switches to a bounded document substring read.
8. **Settings wiring + small UX fixes + test backfill.** `ComplexityAnalyzer.complexityThreshold` reads from `GhostDebuggerSettings`; `ReportGenerator` html-escapes `dateProvider()`; regression tests for every fix above (~25 new tests).

V1.4.0 shipped at ~232 green tests with `verifyPlugin` Compatible across IU 2024.3.2.2 / 2025.1 / 2026.1. V1.4.1 must preserve a green bar (target ~257) and a Compatible verdict against the same matrix.

## 1. Motivation

The post-V1.4 codebase audit (run by Claude on 2026-05-10) surfaced 20 findings across four severity tiers. V1.4.1 addresses everything in **CRITICAL**, **HIGH**, all of **MEDIUM**, plus the cheap **PERFORMANCE** items. Refactor-class **LOW** items (god-class split, service deduplication) defer to V1.5.

| # | Sev | File:line | Item |
|---|---|---|---|
| C1 | Critical | `AnalysisEngine.kt:172` | `runOne` `catch (e: Exception)` returns `emptyList()` without `if (e is ProcessCanceledException) throw e`. Cancel click is silently consumed; subsequent analyzers continue running. Violates CLAUDE.md's PCE rethrow rule and the convention's stated rationale (the IDE assumes cancellable operations are actually cancellable). |
| C2 | Critical | `JcefBridge.kt:91-94, 102-103, 108-109, 113-114, 118-119, 124-126, 132-134, 142-143` | Eight `send*` methods build JSON payloads by hand and escape only `"`. The other half of the methods correctly use `json.encodeToString`; convention is right next door. |
| C3 | Critical | `InMemoryGraph.kt:9-10, 27-28` | `ConcurrentHashMap<String, MutableSet<String>>` with `mutableSetOf()` (= `LinkedHashSet`) inside. Outer thread-safety doesn't propagate to the inner sets. Two analyzers writing edges concurrently to the same source race on `.add()`; risk of `ConcurrentModificationException` or corrupted adjacency. The current static-pass coroutine fan-out (`AnalysisEngine.kt:148-153`) creates the conditions for this. |

PCE inside the cause chain is therefore caught and dropped; the catch-all `Throwable` (line 120) does the same. The reflective dispatch must unwrap and rethrow. |

## 2. Scope decisions (locked in)

| # | Decision | Rationale |
|---|---|---|
| Q1 | **Bundle all CRITICAL + HIGH + MEDIUM + cheap LOW/PERF into one 1.4.1.** | V1.4 ran the same pattern for eleven items; this audit fix is smaller in commit count but similar in scope. Splitting would publish twice for two changelogs without user-visible benefit. |
| Q2 | **`ParsedFile` model change: introduce a `dropContent()` method, keep `content` as `var`.** | Replacing `var content: String` with an immutable design requires propagating a `LiteParsedFile` type through every consumer, which is V1.5-class scope. Naming the operation explicitly removes the mystery without rippling. |
| Q3 | **`NullSafetyFixer`: rewrite on PSI, not extend the regex.** | Trying to harden the regex against strings and comments is a losing game (string templates, raw strings, escaped quotes). The companion `KotlinUnsafeCastFixer` is already PSI-driven; symmetry. |
| Q4 | **`InMemoryGraph` adjacency: `ConcurrentHashMap.newKeySet()`, not `CopyOnWriteArraySet`.** | `add()` happens many times during graph build; CoW would O(n²) the build. Read-mostly access patterns in cycle detection / impact analysis go through `iterator()` of a ConcurrentHashMap-backed set, which provides weak consistency — fine for our use case. |
| Q5 | **`ComplexityAnalyzer` threshold: read from settings, default unchanged at 10.** | The setting already has `maxComplexity` shape in mind from V1.0 design notes; surfacing it in `GhostDebuggerSettings` is ~10 LOC. Changes the spec advertised in the description from documentation lie to truth. |
| Q6 | **JCEF bridge: encode every payload via `Json`, no manual escaping anywhere.** | Half of the methods already do this; finishing the conversion eliminates a bug class rather than narrowly patching the eight call sites. |

### 3.2 PCE rethrow hardening

Two sites:

**`AnalysisEngine.runOne` (line 172):**

```kotlin
} catch (e: Exception) {
    if (e is com.intellij.openapi.progress.ProcessCanceledException) throw e
    log.warn("Analyzer ${analyzer.name} failed; continuing", e)
    emptyList()
}
```

**`CompilationErrorAnalyzer.harvestFile` (lines 117-123):**

```kotlin
} catch (e: InvocationTargetException) {
    val cause = e.cause
    if (cause is com.intellij.openapi.progress.ProcessCanceledException) throw cause
    log.warn("daemon harvest failed for ${parsedFile.path}: ${(cause ?: e).message}")
    emptyList()
} catch (t: Throwable) {
    if (t is com.intellij.openapi.progress.ProcessCanceledException) throw t
    log.warn("daemon harvest failed for ${parsedFile.path}: ${t.message}")
    emptyList()
}
```

`InvocationTargetException` requires unwrapping the cause; the catch-all `Throwable` is the safety net for non-reflective paths. Both must rethrow PCE.

**Test seam:** `AnalysisEngineCancellationTest` already exists. Extend it with one test where the analyzer throws PCE on the third invocation; assert `analyze` propagates PCE rather than returning a partial result.

### 3.3 `JcefBridge` JSON encoding

Replace each hand-built payload with `json.encodeToString(...)`. The serializable shapes already exist for the typed payloads; for the ad-hoc ones (e.g., `sendNodeUpdate`, `sendImpactAnalysis`), use `kotlinx.serialization.json.buildJsonObject` or `mapOf(...)`:

```kotlin
override fun sendNodeUpdate(nodeId: String, status: NodeStatus) {
    val payload = json.encodeToString(mapOf("nodeId" to nodeId, "status" to status.name))
    executeJS("window.__aegis_debug__ && window.__aegis_debug__.onNodeUpdate($payload)")
}
```

Methods to convert: `sendNodeUpdate`, `sendAnalysisComplete`, `sendAnalysisProgress`, `sendError`, `sendSystemExplanation`, `sendImpactAnalysis`, `sendDebugFrame`, `sendDebugStateChanged`. Eight sites; ~30 LOC delta net.

The `executeJS` JavaScript wrapper itself is unchanged — it inlines a serialized JSON literal into the `executeJavaScript(script)` argument. Since `json.encodeToString` produces well-formed JSON (which is also valid JS literal syntax), no further escaping is needed.

### 3.4 `InMemoryGraph` concurrency + iterative DFS

**Adjacency lists:**

```kotlin
private val adjacencyList = ConcurrentHashMap<String, MutableSet<String>>()
private val reverseAdjacencyList = ConcurrentHashMap<String, MutableSet<String>>()
```

becomes:

```kotlin
private val adjacencyList = ConcurrentHashMap<String, MutableSet<String>>()
private val reverseAdjacencyList = ConcurrentHashMap<String, MutableSet<String>>()
// inner sets created via:
adjacencyList.getOrPut(edge.source) { ConcurrentHashMap.newKeySet() }.add(edge.target)
```

`ConcurrentHashMap.newKeySet()` returns a `Set<E>` view backed by `ConcurrentHashMap`. Add/remove are O(1) amortized and thread-safe. Iteration is weakly consistent.

**`findCycles` iterative rewrite:**

```kotlin
fun findCycles(): List<List<String>> {
    cachedCycles?.let { return it }
    val cycles = mutableListOf<List<String>>()
    val visited = mutableSetOf<String>()

    for (root in nodes.keys) {
        if (root in visited) continue
        // Tarjan-style iterative DFS with explicit recursion stack
        data class Frame(val node: String, val iter: Iterator<String>)
        val recursionStack = mutableSetOf<String>()
        val path = mutableListOf<String>()
        val stack = ArrayDeque<Frame>()

        stack.addLast(Frame(root, (adjacencyList[root] ?: emptySet()).iterator()))
        recursionStack.add(root)
        path.add(root)
        visited.add(root)

        while (stack.isNotEmpty()) {
            val top = stack.last()
            if (top.iter.hasNext()) {
                val neighbor = top.iter.next()
                if (neighbor !in visited) {
                    visited.add(neighbor)
                    recursionStack.add(neighbor)
                    path.add(neighbor)
                    stack.addLast(Frame(neighbor, (adjacencyList[neighbor] ?: emptySet()).iterator()))
                } else if (neighbor in recursionStack) {
                    val start = path.indexOf(neighbor)
                    if (start >= 0) cycles.add(path.subList(start, path.size).toList())
                }
            } else {
                recursionStack.remove(top.node)
                path.removeLast()
                stack.removeLast()
            }
        }
    }

    cachedCycles = cycles
    return cycles
}
```

Stack depth becomes a function of available heap, not JVM stack. Behavior preserved (same cycle set, same order).

### 3.5 OkHttp Response in `use { }`

Both AI services pattern:

```kotlin
val response = httpClient.newCall(request).execute()
if (!response.isSuccessful) { ... }
val body = response.body?.string() ?: throw RuntimeException(...)
json.decodeFromString<...>(body)
```

becomes:

```kotlin
httpClient.newCall(request).execute().use { response ->
    if (!response.isSuccessful) {
        val body = response.body?.string() ?: "Unknown error"
        log.error("API error: ${response.code} - $body")
        throw RuntimeException("API communication failure: ${response.code}")
    }
    val body = response.body?.string() ?: throw RuntimeException("Empty response")
    json.decodeFromString<...>(body)
}
```

Connection returns to the pool deterministically on every exit path including JSON parse failure.

### 3.6 `AICache.get` race fix

```kotlin
fun get(key: String): String? {
    val now = Instant.now().epochSecond
    return synchronized(cache) {
        val entry = cache[key] ?: return@synchronized null
        if (now - entry.createdAt.epochSecond > ttlSeconds) {
            cache.remove(key)
            null
        } else {
            entry.response
        }
    }
}
```

Synchronizing on the wrapped `cache` (a `Collections.synchronizedMap`) is correct because `Collections.synchronizedMap` documents the wrapper itself as the synchronization mutex. Read-modify-write is now atomic.

### 3.7 `NullSafetyFixer` PSI-based rewrite

```kotlin
override fun generateFixFromPsi(issue: Issue, file: PsiFile): CodeFix? {
    val ktFile = file as? KtFile ?: return null
    val varName = titleVarRegex.find(issue.title)?.groupValues?.get(1) ?: return null
    val document = PsiDocumentManager.getInstance(file.project).getDocument(ktFile) ?: return null

    // Find the first KtDotQualifiedExpression on the issue's line whose receiver is `varName`
    // and which isn't already a safe-call.
    val target = PsiTreeUtil.findChildrenOfType(ktFile, KtDotQualifiedExpression::class.java)
        .firstOrNull { dot ->
            document.getLineNumber(dot.textOffset) + 1 == issue.line &&
                (dot.receiverExpression as? KtNameReferenceExpression)?.getReferencedName() == varName &&
                dot.operationTokenNode.elementType != KtTokens.SAFE_ACCESS
        } ?: return null

    val original = document.getText(TextRange(
        document.getLineStartOffset(issue.line - 1),
        document.getLineEndOffset(issue.line - 1)
    ))
    val fixed = original.replaceRange(
        target.operationTokenNode.startOffset - document.getLineStartOffset(issue.line - 1),
        target.operationTokenNode.startOffset - document.getLineStartOffset(issue.line - 1) + 1,
        "?."
    )
    if (fixed == original) return null

    return CodeFix(
        id = UUID.randomUUID().toString(),
        issueId = issue.id,
        description = "Add optional chaining: $varName. → $varName?.",
        originalCode = original,
        fixedCode = fixed,
        filePath = issue.filePath,
        lineStart = issue.line,
        lineEnd = issue.line,
        isDeterministic = true,
        confidence = 1.0
    )
}
```

The text-only `generateFix` keeps its current behavior as a regex fallback for non-Kotlin files (TS/JS) where PSI isn't available — but its scope narrows: it returns null when the line text contains a string literal or comment that includes `varName.`. The simpler approach: gate text-mode rewrites on the line passing a "no string or comment containing varName" sniff test.

### 3.8 `NullSafetyAnalyzer` mid-line comment skip + perf

Inline-comment handling:

```kotlin
// Strip mid-line comments before scanning. JS/TS comment forms: //, /* … */
val codeOnly = trimmed.substringBefore("//").let { stripBlockComments(it) }
if (codeOnly.isBlank()) return@forEachIndexed
// ... use codeOnly for the regex match instead of trimmed
```

`stripBlockComments` is a small helper that removes paired `/* … */` substrings on a single line (multi-line blocks aren't handled — accepted limitation; flag at start of `*` already covers JSDoc bodies).

Combined-regex perf:

```kotlin
val varNamesAlternation = nullStateVars.joinToString("|") { Regex.escape(it) }
val combinedRegex = if (nullStateVars.isNotEmpty())
    Regex("""(?<!\?)\b($varNamesAlternation)\.([\w]+)""") else null
// Then per line:
combinedRegex?.findAll(codeOnly)?.forEach { match ->
    val varName = match.groupValues[1]
    // ... existing per-match logic
}
```

O(N) scan per file regardless of `nullStateVars.size`. The pre-check `file.content.contains(varName)` short-circuit for the regex compile happens once.

### 3.9 `ParsedFile.dropContent`

```kotlin
data class ParsedFile(
    val virtualFile: VirtualFile,
    val path: String,
    val extension: String,
    private var _content: String,
    val functions: List<FunctionSymbol> = emptyList(),
    // ...
) {
    val content: String get() = _content
    val lines: List<String> by lazy { _content.lines() }

    /**
     * Frees the in-memory copy of file content after analysis is complete and
     * `lines` (and any other content-derived data) has been materialized. Subsequent
     * reads of `content` will throw IllegalStateException — by design, to surface
     * accidental post-analysis content reads instead of returning silently empty.
     */
    fun dropContent() {
        require(this::lines.isInitialized) {
            "Cannot drop content before lines is materialized; access parsedFile.lines first"
        }
        _content = ""
    }
}
```

`AnalysisEngine.finalize` becomes:

```kotlin
limitedContext.parsedFiles.forEach { it.dropContent() }
```

The naming surfaces the intent. The require-precondition catches the implicit-ordering trap that the current code's `val _lines = file.lines` relies on.

## 6. Risks

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | PCE rethrow surfaces previously-masked bugs | Medium | Low | Cancel-during-analysis was already user-visible (UI froze without progress). Newly-propagated PCE will surface only as cleaner cancellation, not as new errors. |
| R2 | JSON-encoded payloads change shape vs. current hand-built | Medium | Medium | Browser handlers parse via `JSON.parse`; well-formed JSON satisfies them regardless of key order. Add a JCEF-side smoke test in commit 3 that round-trips one event. |
| R3 | Iterative `findCycles` differs from recursive output | Low | Medium | Existing `InMemoryGraphCycleCacheTest` pins behavior; rewrite must keep it green. |
| R4 | Concurrency test flakes in CI | Medium | Low | Use `CountDownLatch` to peak contention, repeat 100×, fail only on consistent failure. |
| R5 | `NullSafetyFixer` PSI rewrite misses cases the regex caught | Medium | Medium | Existing fixer tests stay as a regression bar; add explicit positive cases for `obj.field` (PSI) and explicit negatives for `"obj.field"` (string literal). |
| R6 | `dropContent()` precondition fires for an in-flight test | Low | Low | All call sites are V1.4.1-internal; tests that build `ParsedFile` directly use the constructor and never call `dropContent`. |
| R7 | `ComplexityAnalyzer` settings change breaks existing tests | Low | Low | Default 10 unchanged; existing tests don't assert non-default values. |
| R8 | `ConcurrentHashMap.newKeySet` iteration weakly consistent confuses cycle detection | Low | Low | DFS doesn't depend on snapshot consistency — adjacency reads at iteration time are sufficient. |
