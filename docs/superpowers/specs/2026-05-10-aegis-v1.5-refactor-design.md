# Aegis Debug V1.5 — Pre-V2 refactor: god-class split, BaseAIService extraction

**Date:** 2026-05-10
**Status:** Draft — pending review
**Version target:** `1.5.0` (refactor-class release; bundled commits, V1.4 pattern)
**Base branch:** `main` (after V1.4.1 merges as `<TBD-1.4.1-merge-sha>`)
**Target working branch:** `v1.5-pre-v2-refactor`

---

## 0. Summary

V1.5 lands the two refactor-class items the V1.4.1 audit explicitly deferred (L1: `GhostDebuggerService` god-class split; L3: `BaseAIService` extraction). It is a **pure structural release** — no new analyzer, no new fixer, no new language target, no platform-floor change, no user-visible UI change. The goal is to land the seams V2 will write into *before* V2 starts, not after.

Six dependency-ordered commits on a single `v1.5-pre-v2-refactor` branch:

1. **Marketplace copy + version bump + CHANGELOG stub.** `1.4.1` → `1.5.0` in `build.gradle.kts`, plugin.xml `<change-notes>`, README. CHANGELOG 1.5.0 section. No analyzer/fixer count change — counts are unchanged.
2. **Extract `BaseAIService` (L3).** New abstract class in `com.ghostdebugger.ai` factoring the cache lifecycle, `parseFixResponse`, prompt-builder dispatch, and `AICache` key/get/put dance shared verbatim between `OllamaService` and `OpenAIService`. Subclasses implement one `protected abstract suspend fun callModel(systemPrompt: String, userPrompt: String, jsonMode: Boolean): String`. ~120 LOC of duplication collapses.
3. **Extract `FileChangeWatcher`.** Move VFS-listener registration + debounced auto-refresh logic out of `GhostDebuggerService`. ~40 LOC. Listener still owned via `project.messageBus.connect(disposable)`.
4. **Extract `DebugSessionCoordinator`.** Move `XDebuggerManagerListener` registration, `XDebugSessionListener` attachment, frame extraction, and debug-action dispatch (`stepOver` / `resume` / etc.) out of `GhostDebuggerService`. ~110 LOC. Hosts the `XDebuggerManager.TOPIC` subscription. V2's debug-session cross-check will land here.
5. **Extract `AnalysisOrchestrator`.** Move `analyzeProject`, `performAnalysis`, `reanalyzeFile`, `cascadeDependents`, `cancelAnalysis`, the analysis-lock state, and the test seams (`installTestGraph`, `cascadeDependentsForTest`) into a new project-scoped service. ~300 LOC. V2's test-runner cross-check and `RUNTIME_CONFIRMED` promotion will land here.
6. **Extract `UIEventRouter` + slim `GhostDebuggerService` to facade (~150 LOC).** Move `handleUIEvent` + every `handle*` method (NodeClicked, FixRequested, ApplyFixRequested, ImpactRequested, ExplainSystem, BreakpointSet/Removed, ExportReportRequested) into a new router class. `GhostDebuggerService` becomes a thin facade that owns the project-level state (`currentIssues`, `issuesByFile`, `currentGraph`, `lastInMemoryGraph`, `isAnalyzing`), exposes the `getInstance(project)` entry point its 6 external callers depend on, and delegates everything else.

V1.4.1 ships at ~257 green tests with `verifyPlugin` Compatible across IU 2024.3.2.2 / 2025.1 / 2026.1. V1.5 must preserve a green bar (target ~257, no test-count change since this is pure refactor) and a Compatible verdict against the same matrix. Behavior-pinning tests are the safety net: every test that was green in V1.4.1 must remain green in V1.5 without modification beyond import path adjustments.

## 1. Motivation

The post-V1.4.1 codebase audit (2026-05-10) deferred four LOW/PERF items as refactor-class. V1.5 addresses the two structural ones; the two perf items (P2: `Issue.fingerprint()` memoization; P3: incremental `InMemoryGraph.toProjectGraph`) stay deferred — neither has observed user pain and P3 needs its own design.

| # | Sev | File:line | Item |
|---|---|---|---|
| L1 | Low | `GhostDebuggerService.kt` (918 lines) | God class: holds project state, runs analysis, listens to VFS events, listens to debug events, routes UI events, exports reports, builds local fallback summaries. Touched by 6 distinct external callers (`AnalyzeProjectAction`, `ExplainSystemAction`, `GhostDebuggerToolWindowFactory`, `NeuroMapPanel`, `GhostDebuggerAnnotator`, `setBridge` from `JcefBridge`). Splitting needs careful test partitioning. |
| L3 | Low | `OllamaService.kt` (146 lines), `OpenAIService.kt` (163 lines) | ~92% byte-identical structure. `AICache` field, `Json { ignoreUnknownKeys = true }`, the `httpClient` builder with timeout config, `parseFixResponse()`, and the cache-key / cache-get / cache-put pattern in `explainIssue`, `suggestFix`, `explainSystem` are duplicated verbatim. Only the wire-shape (`OllamaChatRequest`/`Response` vs. `ChatCompletionRequest`/`Response`), the auth header, and the `jsonMode` flag actually differ. |

**Why land these now, before V2:**

V2's scope (`docs/aegis_debug_roadmap_v2_to_v5.md`) introduces five capabilities that will land in or adjacent to today's god class:

- **Test-runner cross-check** — hooks `JUnitConfiguration` / test runner events, correlates executed lines with static findings, promotes findings to `RUNTIME_CONFIRMED`. Natural home: `AnalysisOrchestrator` (where `performAnalysis` lives today).
- **Debug-session cross-check** — observes variable values at breakpoints, confirms/demotes null-safety findings. Natural home: `DebugSessionCoordinator` (where `XDebuggerManagerListener` plumbing lives today).
- **Problems-tool-window integration** — registers issues with `WolfTheProblemSolver`. Natural home: a new sibling of `UIEventRouter` or an additional emit path inside it.
- **IntentionAction quick-fixes** — exposes `FixerRegistry` entries to `Alt+Enter`. Natural home: a new annotator-like class; not in `GhostDebuggerService`.
- **Streaming AI responses** — replaces "wait then paste" with token streaming. Natural home: `BaseAIService` (where `callModel` would gain a streaming overload).

If these land in V2 directly on top of today's `GhostDebuggerService`, the class grows from 918 → ~1500 LOC and the test partitioning gets harder, not easier. Splitting now means each V2 feature lands on a clean seam.

**Why this is the entire scope:**

V1.5 is deliberately the **smallest scope that unblocks V2**. No feature work, no analyzer, no fixer, no platform bump. The release exists to convert deferred refactor debt into landed structural work, then close.

## 2. Scope decisions (locked in)

| # | Decision | Rationale |
|---|---|---|
| Q1 | **Bundle L1 + L3 into one 1.5.0 release.** | Both are pure refactors with the same risk profile (test partitioning) and the same rationale (clear seams before V2). Splitting into 1.5.0 (L3) + 1.5.1 (L1) would publish twice for two changelogs without user-visible benefit. |
| Q2 | **Keep `GhostDebuggerService` name and `getInstance(project)` entry point.** | Six external callers depend on `GhostDebuggerService.getInstance(project)`. Renaming the facade ripples through `actions/`, `toolwindow/`, `annotator/`, and the JCEF bridge — and breaks third-party plugins that reflect into `com.ghostdebugger.GhostDebuggerService`. The facade keeps its identity; behavior moves out. |
| Q3 | **Project-scoped `@Service` for each extracted class** (`AnalysisOrchestrator`, `UIEventRouter`, `FileChangeWatcher`, `DebugSessionCoordinator`). | Project-level state lives on each. The IntelliJ Service Container handles lifetime + disposal. Avoids constructor-injection sprawl and keeps `getInstance(project)` as the canonical access pattern, mirroring the existing `GhostDebuggerService` shape. |
| Q4 | **`BaseAIService` is an `abstract class`, not an `interface`.** | The shared state — `cache`, `json`, `httpClient`, `parseFixResponse` — is concrete. An interface would force every subclass to redeclare the field set or repeat the cache-orchestration logic, which is exactly the duplication we're eliminating. Abstract class with one `protected abstract suspend fun callModel(...)` collapses the duplication cleanly. |
| Q5 | **No change to `AIService` interface visibility.** | `AIService` (the public contract used by `AIServiceFactory` and `GhostDebuggerService`) stays unchanged. `BaseAIService` is an internal implementation detail; subclasses still implement `AIService`. Callers of `AIServiceFactory.create(...)` see no diff. |
| Q6 | **Test seams move with their state.** | `installTestGraph` and `cascadeDependentsForTest` move to `AnalysisOrchestrator` (they manipulate analysis state). `setBridgeForTest` stays on `GhostDebuggerService` (the facade owns the bridge). Existing `GhostDebuggerServiceCascadeTest` and friends gain a one-line indirection (`service.orchestrator.installTestGraph(...)`) — `internal fun` accessor on the facade preserves the test surface. |
| Q7 | **No new public API.** | Every new class is `internal` in the `com.ghostdebugger.*` package. No `@ApiStatus.Experimental` markers; no plugin-extension points; no third-party hook. Surfacing structural changes as public API would commit V1.5 to backwards-compatibility on a layout that V2 will re-shape; we keep flexibility. |
| Q8 | **No `kotlinx.coroutines.flow` migration.** | The current `CoroutineScope + scope.launch + withContext(Dispatchers.Swing)` pattern stays. Migrating to `Flow`-based event emission would be a behavior-impacting change disguised as cleanup; that's V2-class scope, not refactor-class. |

### 3.8 `BaseAIService` extraction (L3)

The shared parent:

```kotlin
internal abstract class BaseAIService(
    protected val cacheTtlSeconds: Long,
    protected val cacheEnabled: Boolean,
    protected val cacheMaxEntries: Int,
    protected val timeoutMs: Long
) : AIService {
    protected val log = logger<BaseAIService>()
    protected val cache = AICache(cacheTtlSeconds, cacheMaxEntries)
    protected val json = Json { ignoreUnknownKeys = true }

    protected val httpClient: OkHttpClient = OkHttpClient.Builder()
        .connectTimeout(timeoutMs, TimeUnit.MILLISECONDS)
        .readTimeout(timeoutMs, TimeUnit.MILLISECONDS)
        .writeTimeout(timeoutMs, TimeUnit.MILLISECONDS)
        .build()

    /**
     * Provider-specific HTTP call. Subclass implements the request shape, auth, and response decode.
     * Receives the system + user prompt and a `jsonMode` hint (Ollama ignores it; OpenAI sets `response_format`).
     */
    protected abstract suspend fun callModel(
        systemPrompt: String,
        userPrompt: String,
        jsonMode: Boolean
    ): String

    override suspend fun detectIssues(
        filePath: String,
        fileContent: String,
        functions: List<FunctionSymbol>
    ): List<Issue> {
        return try {
            val raw = callModel(SystemPrompts.DEBUGGER, PromptTemplates.detectIssues(filePath, fileContent, functions), jsonMode = true)
            when (val r = AiJsonExtractor.extract(raw)) {
                is AiJsonExtractor.Result.Ok -> AiIssueMapper.mapIssues(r.element, filePath, fileContent)
                AiJsonExtractor.Result.Empty -> {
                    log.warn("${this::class.simpleName} JSON extraction returned Empty for $filePath (len=${raw.length})")
                    emptyList()
                }
            }
        } catch (e: Exception) {
            if (e is ProcessCanceledException) throw e
            log.warn("${this::class.simpleName} detectIssues failed for $filePath", e)
            emptyList()
        }
    }

    override suspend fun explainIssue(issue: Issue, codeSnippet: String): String =
        cached(codeSnippet + issue.type.name, "explain") {
            callModel(SystemPrompts.DEBUGGER, PromptTemplates.explainIssue(issue, codeSnippet), jsonMode = false)
        }

    override suspend fun suggestFix(issue: Issue, codeSnippet: String): CodeFix {
        val raw = cached(codeSnippet + issue.type.name, "fix") {
            callModel(SystemPrompts.DEBUGGER, PromptTemplates.suggestFix(issue, codeSnippet), jsonMode = false)
        }
        return parseFixResponse(raw, issue, codeSnippet)
    }

    override suspend fun explainSystem(graph: ProjectGraph): String =
        cached(graph.metadata.projectName + graph.nodes.size, "system") {
            callModel(SystemPrompts.DEBUGGER, PromptTemplates.explainSystem(graph), jsonMode = false)
        }

    /** Unified cache-orchestration helper: collapses 12 LOC of cache-key/get/put across 3 methods × 2 services. */
    private suspend inline fun cached(seed: Any, kind: String, crossinline produce: suspend () -> String): String {

        if (key != null) cache.get(key)?.let { return it }
        val response = produce()
        if (key != null) cache.put(key, response)
        return response
    }
```

```kotlin
internal class OllamaService(
    internal val endpoint: String,
    internal val model: String,
    timeoutMs: Long = 30_000,
    cacheTtlSeconds: Long = 3600,
    cacheEnabled: Boolean = true,
    cacheMaxEntries: Int = 256
) : BaseAIService(cacheTtlSeconds, cacheEnabled, cacheMaxEntries, timeoutMs) {

    override suspend fun callModel(systemPrompt: String, userPrompt: String, jsonMode: Boolean): String =
        withContext(Dispatchers.IO) {
            val body = json.encodeToString(OllamaChatRequest(model, listOf(
                ChatMessage("system", systemPrompt.trimIndent()),
                ChatMessage("user", userPrompt)
            ))).toRequestBody("application/json".toMediaType())

            val req = Request.Builder().url("$endpoint/api/chat").post(body).build()
            httpClient.newCall(req).execute().use { resp ->
                if (!resp.isSuccessful) {
                    val errBody = resp.body?.string() ?: "unknown error"
                    log.error("Ollama API error: ${resp.code} — $errBody")
                    throw RuntimeException("Ollama API error: ${resp.code}")
                }
                val rb = resp.body?.string() ?: throw RuntimeException("Empty response from Ollama")
                json.decodeFromString<OllamaChatResponse>(rb).message.content
            }
        }
}
```

### Commit 2 — Extract `BaseAIService` (L3)

- New `src/main/kotlin/com/ghostdebugger/ai/BaseAIService.kt`.

### Commit 5 — Extract `AnalysisOrchestrator` + `ReportExporter`

- New `src/main/kotlin/com/ghostdebugger/AnalysisOrchestrator.kt`. Moves `analyzeProject`, `performAnalysis`, `cancelAnalysis`, `reanalyzeFile`, `cascadeDependents` + state (`analysisLock`, `activeAnalysisIndicator`, `lastIssueFingerprints`, `fixApplicator` for the reanalyze-tail).

- Test seams `installTestGraph`, `cascadeDependentsForTest` move to `AnalysisOrchestrator`; the facade's `internal fun`s become 1-line delegators.
- `plugin.xml`: register `AnalysisOrchestrator` as a `<projectService>`.
- New `AnalysisOrchestratorTest`: pin facade delegation (call counts), pin `cancelAnalysis` propagation.

**Risk: medium-high.** This is the largest single move. The state-sharing pattern (orchestrator reads `service.currentIssues`, writes via `service.updateIssues`) needs careful audit — every `currentIssues = ...` mutation in V1.4.1 maps to a `service.updateIssues(...)` call after the move. OQ2 captures this audit.

The pre-V1.5 `lastIssueFingerprints` lives on `GhostDebuggerService` but is only ever read/written inside `performAnalysis`. Moving it to `AnalysisOrchestrator` is a pure-private-state move; no facade touchpoint needed.

The reanalysis tail in `handleApplyFixRequested` (now in `UIEventRouter`) calls `orchestrator.reanalyzeFile(filePath)` — a clean cross-service call.

- The `aiService` cache + `resolveAiService()` move to the router (every AI-touching handler is a router method).
- New `UIEventRouterTest` and `GhostDebuggerServiceFacadeTest`.

**Risk: medium.** The handlers are independent in V1.4.1 (no cross-handler state beyond `currentIssues` / `aiService`), so the move is mechanical. The risk is in the `aiService` field: V1.4.1 caches the resolved service across calls (`private var aiService: AIService? = null` at `GhostDebuggerService.kt:82`), so resetting it via settings change would require a recompute. ## 11. Why this matters for V2

This section is non-binding context — V2 is its own spec — but it explains why V1.5 is the right next step instead of opening V2 directly.

V2's roadmap headline is **dynamic validation**: a `RUNTIME_CONFIRMED` provenance tier promoted from test-runner cross-check and debug-session cross-check. The two new code paths land here:

- **Test-runner cross-check** registers a listener on `JavaTestFrameworkRunnableState` (or equivalent), correlates executed lines with `currentIssues`, and calls a new method like `service.promoteToRuntimeConfirmed(issueIds)` on the orchestrator. **Lands in `AnalysisOrchestrator`** (V1.5) — not in a 918-line `GhostDebuggerService`.
- **Debug-session cross-check** extends `DebugSessionCoordinator.sendCurrentDebugFrame` with a "for each null-safety issue at this line, observe the variable's value, demote if non-null" branch. **Lands in `DebugSessionCoordinator`** (V1.5) — clean seam, no other concerns to navigate around.

The other V2 items (Python, Problems-tool-window, IntentionAction, streaming AI) similarly land on V1.5 seams: Python adds analyzers/fixers (no `GhostDebuggerService` touch); Problems-tool-window registers issues in a new sibling of `UIEventRouter`; IntentionAction is a fresh annotator-style class; streaming AI extends `BaseAIService` with a `streamCallModel` overload.

If V1.5 doesn't land first, V2's PRs each grow `GhostDebuggerService` by ~100 LOC and re-introduce the duplication in the AI services. By V2 GA, the god class is ~1500 LOC and V3 inherits a worse refactor problem than V1.5 solves today.
