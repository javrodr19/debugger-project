# Aegis Debug V1.5 — Pre-V2 refactor (god-class split + BaseAIService) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the two refactor-class items the V1.4.1 audit deferred (L1: `GhostDebuggerService` god-class split; L3: `BaseAIService` extraction). Pure structural release — no new analyzer, fixer, language, or UI surface. Six dependency-ordered commits on `v1.5-pre-v2-refactor`.

**Architecture:** `GhostDebuggerService` (918 LOC) shrinks to a ~150 LOC facade over four project-scoped collaborators (`AnalysisOrchestrator`, `UIEventRouter`, `FileChangeWatcher`, `DebugSessionCoordinator`) plus one plain-class helper (`ReportExporter`). State (`currentIssues`, `currentGraph`, `lastInMemoryGraph`, `suppressUntil`) stays on the facade as the single writer surface; collaborators read via `service.X` and mutate via `service.updateIssues(...)`. `OllamaService` and `OpenAIService` extend a new `BaseAIService` abstract class that owns the cache, JSON setup, HTTP client, `parseFixResponse`, and `detectIssues` orchestration; subclasses implement only `protected abstract suspend fun callModel(...)`.

**Tech Stack:** Kotlin 2.0.21, IntelliJ Platform Gradle Plugin 2.14.0, target IDE `intellijIdeaCommunity("2024.3.2")`, JDK 21 via IDE-bundled JBR (`JAVA_HOME` quirk documented in CLAUDE.md), JUnit Jupiter + JUnit Vintage (`BasePlatformTestCase`), OkHttp 4.x, kotlinx.serialization 1.x.

**Spec reference:** `docs/superpowers/specs/2026-05-10-aegis-v1.5-refactor-design.md`.

**Spec adjustments recorded here:** any divergence from spec discovered during execution gets a `### Plan note` in the relevant task.

```markdown
`GhostDebuggerService` is the canonical project-level state holder for analysis

`UIEventRouter`, `FileChangeWatcher`, `DebugSessionCoordinator`) **read** state

`internal fun updateIssues(...)` mutator. Direct assignment from a collaborator

re-introduces the scattered mutation V1.5 was designed to eliminate.

The reason this matters: V2 will add new collaborators (test-runner cross-check,
problems-tool-window emit path) that read the same state. If each collaborator
owns its own copy, the cross-collaborator views drift and the user sees stale
or contradictory issues across surfaces. One writer, many readers — through
the facade.
```
