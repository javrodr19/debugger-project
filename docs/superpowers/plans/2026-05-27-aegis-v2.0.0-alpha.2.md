# Aegis Debug V2.0.0-alpha.2 — Finish the runtime-tier story — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the dynamic-validation thesis by adding the two signal sources alpha.1 left out (test-suite cross-check + `STATE_BEFORE_INIT` debug correlation) and surfacing every finding in the native Problems tool window.

**Architecture:** Test-suite cross-check lives in `AnalysisOrchestrator` behind a `TestStatusListener` registered at orchestrator init. `STATE_BEFORE_INIT` correlation extends `DebugSessionCoordinator.performDebugSessionCrossCheck` by widening the issue-type filter — pure additive. Problems-tool-window emit lives in a new project-scoped `ProblemsViewCoordinator` service that subscribes to `GhostDebuggerService.updateIssues` via a new `onIssuesUpdated` callback registry on the facade and publishes to `WolfTheProblemSolver`. State ownership stays on the facade per the V1.5 rule.

**Tech Stack:** Kotlin 2.0.21, IntelliJ Platform Gradle Plugin 2.14.0, target IDE `intellijIdeaCommunity("2024.3.2")`, JDK 21 via IDE-bundled JBR, JUnit Jupiter + JUnit Vintage (`BasePlatformTestCase`).

**Spec reference:** `docs/superpowers/specs/2026-05-27-aegis-v2.x-continuation-design.md` §3.2.

**Spec adjustments recorded here:** any divergence from spec discovered during execution gets a `### Plan note` in the relevant task.

**Files:** `src/main/kotlin/com/ghostdebugger/GhostDebuggerService.kt`.

**Rationale:** `ProblemsViewCoordinator` needs to react to issue updates without polling. The facade owns the writer surface (`updateIssues`); a subscribe-on-update callback keeps the V1.5 single-writer rule intact.

- [ ] **Step 1: Add the callback list and accessors**

In `GhostDebuggerService`:

```kotlin
private val issuesUpdateListeners = mutableListOf<(List<Issue>) -> Unit>()

internal fun onIssuesUpdated(listener: (List<Issue>) -> Unit) {
    issuesUpdateListeners += listener
}

internal fun removeIssuesListener(listener: (List<Issue>) -> Unit) {
    issuesUpdateListeners -= listener
}
```

- Remove the listener, call `updateIssues` again, assert no further invocation.

## Task 2: Implement `ProblemsViewCoordinator`

**Files:** `src/main/kotlin/com/ghostdebugger/ProblemsViewCoordinator.kt`, `src/main/resources/META-INF/plugin.xml`.

**Rationale:** Native Problems-tool-window emit so keyboard-driven users see Aegis findings alongside compiler problems.

- [ ] **Step 1: Create the service skeleton**

```kotlin
@Service(Service.Level.PROJECT)
internal class ProblemsViewCoordinator(private val project: Project) : Disposable {
    private val log = logger<ProblemsViewCoordinator>()
    private val service get() = GhostDebuggerService.getInstance(project)
    private val listener: (List<Issue>) -> Unit = { issues -> publishToProblemsView(issues) }
    @Volatile private var lastPublishedByFile: Map<String, Set<String>> = emptyMap()

    init {
        Disposer.register(project, this)
    }

    fun start() {
        service.onIssuesUpdated(listener)
    }

    override fun dispose() {
        service.removeIssuesListener(listener)
    }

    companion object {
        fun getInstance(project: Project): ProblemsViewCoordinator =
            project.getService(ProblemsViewCoordinator::class.java)
    }
}
```

- [ ] **Step 2: Implement `publishToProblemsView`**

Diff `issues` against `lastPublishedByFile` (keyed by file path, value = set of issue IDs). For each file whose set changed:

- Convert the new issue set into `Problem` objects via
  `WolfTheProblemSolver.getInstance(project).convertToProblem(...)` (one per issue,
  carrying issue title + severity + line).
- Call `WolfTheProblemSolver.getInstance(project).reportProblems(virtualFile, problems)`
  on the EDT (wrap in `ApplicationManager.getApplication().invokeLater { }`).
- For files where the new set is empty, call `clearProblems(virtualFile)`.

Update `lastPublishedByFile` after each successful publish.

Wrap the whole thing in a `try`/`catch (e: Exception)` with the standard PCE rethrow.

- [ ] **Step 3: Register the service in `plugin.xml`**

Inside the `<extensions defaultExtensionNs="com.intellij">` block, alongside the other V1.5 collaborator registrations:

```xml
<!-- V2.0.0-alpha.2: native Problems tool window emit -->
<projectService
    serviceImplementation="com.ghostdebugger.ProblemsViewCoordinator"/>
```

- [ ] **Step 4: Start the coordinator from `setBridge`**

Open `GhostDebuggerService.setBridge` (where the other coordinators are started). Add:

```kotlin
ProblemsViewCoordinator.getInstance(project).start()
```

- [ ] **Step 5: Add an integration test**

`src/test/kotlin/com/ghostdebugger/ProblemsViewCoordinatorTest.kt` extending `BasePlatformTestCase`:

- Mock `WolfTheProblemSolver` (use `mockk` per existing test setup).
- Get the service, call `start()`, then `service.updateIssues(listOf(fakeIssueOnFooKt))`.
- Verify `WolfTheProblemSolver.reportProblems` was called with the expected virtual file.
- Call `updateIssues(emptyList())`, verify `clearProblems` was called.

- [ ] **Step 6: Compile + test**

## Task 3: Test-suite cross-check in `AnalysisOrchestrator`

**Files:** `src/main/kotlin/com/ghostdebugger/AnalysisOrchestrator.kt`, `src/test/kotlin/com/ghostdebugger/AnalysisOrchestratorTestRunnerTest.kt`.

**Rationale:** The V2 thesis — runtime confirmation needs to fire on every test run, not just on explicit debug sessions, or users won't see the benefit.

- [ ] **Step 1: Register `TestStatusListener` in orchestrator init**

```kotlin
init {
    Disposer.register(project, this)
    val testListener = object : TestStatusListener() {
        override fun testSuiteFinished(root: AbstractTestProxy?) {
            if (root != null) handleTestSuiteFinished(root)
        }
    }
    TestStatusListener.EP_NAME.point.registerExtension(testListener, this)
}
```

Wrap in `try`/`catch (e: Exception)` with PCE rethrow. If registration fails (e.g., in a headless test environment without the test runner plugin), log a warn and continue.

- [ ] **Step 2: Implement `handleTestSuiteFinished`**

Walk the proxy tree depth-first. For each failed leaf:

- Parse `proxy.stacktrace` into `(filePath, line)` pairs using a stack-frame regex.
  Kotlin/Java JVM frames look like `at com.foo.Bar.method(Bar.kt:42)`; JS frames look
  like `at method (path/to/file.js:42:7)`. Ship a small parser covering both.
- For each `(filePath, line)`, find matching static findings via
  `service.issuesByFile[normalize(filePath)]?.filter { it.line == line }`.
- Build a new issue list with each match promoted to `RUNTIME_CONFIRMED` (confidence
  `1.0`), then call `service.updateIssues(updatedList)` once at the end (single batched
  write, not per-finding).

- [ ] **Step 3: Add `coverageReached` flag handling (covered-but-not-failing)**

This requires the user to have run with coverage. Read `CoverageDataManager.getInstance(project).currentSuitesBundle?.coverageEngine?.createCoverageSuite(...)` to get the suite, then walk the covered-line map. Findings on covered-but-not-failing lines get `LIKELY` confidence (`0.7`). Findings on uncovered lines get an `coverageReached = false` annotation surfaced as the "needs test coverage" hint.

If coverage data is null (no coverage suite ran), skip this step silently — alpha.2 must work without coverage.

### Plan note: the coverage path is the higher-risk part of this task. If we can't make it work cleanly in one day, ship alpha.2 with failing-test promotion only and defer coverage-derived `LIKELY` to alpha.3 or beta.1.

- [ ] **Step 4: Add tests**

`AnalysisOrchestratorTestRunnerTest`:

- Build a fake `AbstractTestProxy` tree with one failed leaf whose stacktrace points to a known line in a known file.
- Pre-populate `service` with a matching static finding at that line.
- Invoke `handleTestSuiteFinished(rootProxy)` directly.
- Assert the finding's `sources` now contains `RUNTIME_CONFIRMED` and `confidence == 1.0`.

- [ ] **Step 5: Compile + test**

```bash
./gradlew test --tests "com.ghostdebugger.AnalysisOrchestratorTestRunnerTest" -x npmInstallWebview -x buildWebview -x processResources -x processTestResources
```

Green before moving on.

## Task 4: Extend debug-session cross-check to `STATE_BEFORE_INIT`

**Files:** `src/main/kotlin/com/ghostdebugger/DebugSessionCoordinator.kt`, `src/test/kotlin/com/ghostdebugger/DebugSessionCoordinatorTest.kt`.

**Rationale:** The roadmap pairs null-safety and state-before-init for debug cross-check. Alpha.1 only shipped the first; alpha.2 closes the gap.

- [ ] **Step 1: Widen the filter**

In `performDebugSessionCrossCheck`:

```kotlin
val relevantIssues = service.currentIssues.filter {
    it.filePath.replace("\\", "/") == normalizedPath &&
    it.line == line &&
    (it.type == IssueType.NULL_SAFETY || it.type == IssueType.STATE_BEFORE_INIT)
}
```

- [ ] **Step 2: Extend the value-interpretation logic**

In both `setPresentation` overrides inside the `XValueNode` anonymous class:

For `STATE_BEFORE_INIT` findings, the "bad" condition is the value being null *or* the rendered presentation containing the substrings `"uninitialized"`, `"<not initialized>"`, or `"this object is not yet initialized"` (the JDWP / JVMTI markers the JetBrains debugger surfaces for uninitialized JVM fields).

Refactor:

```kotlin
val isBadValue = when (issue.type) {
    IssueType.NULL_SAFETY -> value == "null" || value == "undefined"
    IssueType.STATE_BEFORE_INIT -> value == "null" || value == "undefined" ||
        value.contains("uninitialized", ignoreCase = true) ||
        value.contains("not initialized", ignoreCase = true)
    else -> false
}
updateIssueWithDebuggerResult(issue, isBadValue)
```

Apply the same change in the presentation-rendering `setPresentation` overload (the one that walks `XValuePresentation.XValueTextRenderer`).

- [ ] **Step 3: Extend `extractVariableName` to handle state-before-init titles**

State-before-init findings have titles like "Variable 'count' read before assignment". Extend the regex:

```kotlin
val varRegex = "Variable '([^']+)'|Nullable '([^']+)'|Expression '([^']+)'|Null reference: (\\w+)|read before assignment: (\\w+)".toRegex()
```

- [ ] **Step 4: Update the existing test**

In `DebugSessionCoordinatorTest`, add cases:

```kotlin
assertEquals("count", coordinator.extractVariableName(
    "State read before init: count",
    "Variable 'count' read before assignment in constructor"
))

assertEquals("score", coordinator.extractVariableName(
    "read before assignment: score",
    "Field 'score' is read before being assigned"
))
```

- [ ] **Step 5: Compile + test**

```bash
./gradlew test --tests "com.ghostdebugger.DebugSessionCoordinatorTest" -x npmInstallWebview -x buildWebview -x processResources -x processTestResources
```

Green before moving on.
